# HAM data flow in this source snapshot

HAM connects directly to the Home Assistant address entered by the user. Its OAuth WebView receives the Home Assistant authorization response inside the app. Access and refresh tokens and the server address are held in Android Keystore-backed encrypted private preferences. Calendar lists, events, and open to-do items are loaded into process memory. Local preferences include calendar favorites, hidden calendar IDs, an optional explicit default, recent selections, and connection/refresh times. Android app backup is disabled in the manifest.

Calendar reads and supported create/title-edit requests go to the chosen Home Assistant server. The selected calendar's exact entity ID is used for writes and its current capability is checked before creation. Clearing loaded information removes in-memory data; disconnect removes the local session. Requesting revocation asks Home Assistant to revoke the refresh token and reports whether the request was accepted.

Screenshot import performs OCR on the device. The reviewed, unsaved event details are encrypted with an Android Keystore key in private app preferences; the source image is stored separately in app-private files and is **not encrypted by HAM**. When the user chooses address verification, HAM sends only the entered venue and address search words to OpenStreetMap Nominatim over HTTPS. The query does not contain the screenshot, event title, calendar list, or Home Assistant credentials. Nominatim and the network path can observe ordinary connection metadata and the query. Tapping Maps passes the address to the selected map app; that app may make its own network requests. If the user saves with an attachment, the image is sent to the chosen Home Assistant server's authenticated HAM attachment endpoint. That endpoint stores image bytes and owner metadata in the server's private `.storage` area; HAM does not encrypt those server-side bytes. Server administrators and their backups can access them. The calendar event stores a reference to the attachment.

The HAM website is an OAuth client identity and software distribution site. Home Assistant may fetch the identity page; HAM does not send calendar contents or authorization codes to it. Direct DEV builds query the public DEV update feed at app launch and on manual request. Choosing Update now downloads the APK from the public site before Android asks for installation approval. These website requests expose ordinary network metadata, not Home Assistant credentials or calendar contents. Direct Stable has a separate future update feed; Play and F-Droid flavors defer to their distribution channels. The current source snapshot uses no advertising, analytics, crash-reporting, or remote OCR SDK.

The Home Assistant connection is encrypted only when the owner chooses an HTTPS server address. HAM permits HTTP for private-network hosts after warning that the connection is unencrypted. Calendar-selection preferences and connection timestamps are private app settings, not Keystore-encrypted secrets. Android app backup is disabled. This is source-level documentation, not proof of every possible runtime network behavior.

The effective public [Privacy Policy](https://tinkercobble.com/ham/privacy/) describes current user-facing practices. Recheck the runtime behavior and policy whenever data handling changes.
