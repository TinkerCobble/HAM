# HAM data flow in the canonical source

Code130 update path: the app checks only the canonical public HTTPS update feed. On Android 12+ an enabled background worker may download a newer APK on an unmetered network, verify its SHA-256, canonical package, higher version and installed signing identity, then ask Android PackageInstaller for a self-update without a foreground prompt. Android may still require approval, in which case HAM offers its existing manual update path next time it opens. This uses an app-private APK cache and stores no account, calendar, event or device identifier in the work request. The owner can turn automatic installation off in Settings. Network requests expose ordinary request metadata to the website host; no calendar or account payload is sent.

Code127 event entry: typed times, suggested durations, date choices and OCR venue classification run on-device. Unfinished Quick Add text is encrypted in app-private storage with a dedicated Android Keystore key. The screenshot review draft also retains the original OCR text under its existing protected store; the image remains app-private without additional HAM encryption. Address verification is off by default. After opt-in and entry of a complete street address, HAM calls Android's Geocoder once for that address; Android's location service may send it to its provider. HAM does not send event titles, calendar contents or screenshot images for this lookup, and no returned address replaces the original until selected. An unavailable lookup never blocks saving. The old direct Nominatim lookup has been removed. No new permission, TinkerCobble endpoint or AI scheduling path is introduced.

Code125 permission handling: the foreground Android Calendar Provider observer starts only after Android calendars are enabled and the app has current `READ_CALENDAR` permission. A permission-race denial leaves the observer unregistered. No new permission, account flow, endpoint, stored field or third-party transfer is introduced.

HAM is a native Android application. It calls the Home Assistant server, Android Calendar Provider, and calendar services that the user connects. Calendar providers own their records. HAM has no TinkerCobble account, analytics, advertising, AI scheduling service, or hosted calendar backend.

Home Assistant authorization runs through its own sign-in and consent screen. HAM receives the Android callback and stores access and refresh tokens in Keystore-protected app-private storage. The public HAM website is the OAuth client identity and software download site; it does not receive authorization codes or calendar records. The app supports a compatibility sign-in when a Home Assistant server does not advertise PKCE S256. It uses PKCE S256 when supported. Home Assistant tokens may authorize more than calendar access; HAM does not describe them as calendar-only.

Calendar lists, events, app preferences, selected sources, cached views, saved groups, local tasks, templates, and pending offline changes stay on the device. Sensitive account details, private feed URLs, cached records, and pending changes use app-private protected storage where their respective stores specify it. Android backup is disabled in the manifest. The user may export selected information through Android's document picker or create an encrypted local backup; the selected destination then receives those bytes. Calendar changes are sent directly to the selected provider and retained for review if HAM cannot confirm a write.

Android Calendar Provider access uses Android calendar permissions and only the selected calendars are displayed. Existing Android account sync, including Google where configured, is controlled by Android and the provider. iCloud and generic CalDAV connect directly to their HTTPS endpoints using credentials entered in HAM. Read-only ICS subscriptions connect directly to the supplied feed; private URLs are treated as sensitive. Home Assistant and CalDAV writes are capability-gated and conditional where supported. Providers can see the event details sent for a requested write and ordinary network metadata.

Screenshot import performs OCR on-device. The reviewed text is protected in app-private storage; the source image is app-private but is **not additionally encrypted by HAM**. Optional address verification uses Android's Geocoder as described above. Tapping Maps passes the address to the chosen map app. An attachment saved to a Home Assistant server is accessible to its authorized administrators and backups; HAM does not add server-side encryption.

The public download page and any enabled update check receive ordinary network metadata such as IP address, path, and time. They receive no HAM credentials or calendar content from the app. The exact external destinations, storage behavior, permissions, and legal copy require renewed review when the app changes. See the [current privacy policy](https://tinkercobble.com/ham/privacy/).
