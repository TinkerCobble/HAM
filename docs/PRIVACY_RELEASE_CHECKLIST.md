# HAM privacy gate for public files

Use this before a public source push or a direct APK publication. `scripts/privacy_check.py` checks first-party source and privacy-sensitive architecture; Gitleaks scans the current files and every reachable public commit, branch, and tag. `scripts/privacy_artifacts.py` checks the exact APK, matching source ZIP, HAM product and legal pages, shared stylesheet, checksums, and update feed. The workflow runs these checks independently, and any failure blocks a green result. The pinned release URLs and hashes are in `release/privacy-artifacts.json`.

1. Inspect the source diff, filenames, commit authors, tests, fixtures, screenshots, image metadata, and third-party notices. Keep real calendar/entity names, event details, private screenshots, addresses, contacts, Home Assistant configuration, credentials, signing material, device IDs, and local paths out of public source and release files. Use synthetic examples.
2. Scan all reachable Git history with the pinned Gitleaks release, then scan the current working tree. Run `python scripts/privacy_check.py`. Do not interpret a zero exit code as complete privacy proof.
3. For a new direct APK, set the candidate URL and verified SHA-256 in `release/privacy-artifacts.json`, and run `python scripts/privacy_artifacts.py --staged --apk <signed-apk> --source-zip <matching-source-zip> --website-dir <website-site-directory>` against the **actual** prepared files. Inspect packaged APK contents, image metadata, and expected package/signature/version separately. Review the source archive against the exact source commit; these checks do not prove build reproducibility.
4. Review local storage and backup behavior, app logging, and every external network destination. Test only with synthetic data in an isolated environment. Confirm that address lookup sends only the venue/address query, that Home Assistant attachment access requires authentication, and that legal copy says precisely what is encrypted, merely private, or sent off-device.
5. Publish the verified APK and matching source first. Confirm live download hashes and scan the live pages/files. Update the public feed last. Do not advance a feed to an unverified file. Direct updates remain user-approved through Android.

The public workflow's live-artifact job audits the currently pinned release. It is not a substitute for the staged-file run before a future website or R2 upload. If a finding appears, stop publication and keep details private; do not add a broad scanner exclusion. History rewrites, credential changes, and deletion of published artifacts require owner approval.
